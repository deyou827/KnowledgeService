# 数据库迁移

使用 Alembic 管理 PostgreSQL 业务表、任务表及检索结构的版本迁移。目录独立于应用包，迁移是显式一次性作业；API 与 Worker 启动不自动并发修改数据库。

S1a 随数据库模型建立实际配置与迁移脚本，本轮没有可执行迁移。数据库表由领域关系与核心链路推导，不直接持久化 LangChain／LlamaIndex 对象，也不为框架创建第二套权威文档库。

分阶段表、Scope 复合外键、不可变产物、向量维度约束和迁移顺序见[核心链路详细设计第 7 节](../docs/KnowledgeService-核心链路详细设计.md#7-核心数据库设计)。S1a 不提前创建全部内容、模型与评测表；S3 的词法到混合索引迁移由任务构建和发布完成。

结构迁移与文档重解析／重建向量区分：后者由可靠任务构建新索引版本并经检查发布，不在一次表结构迁移中调用外部模型。回滚与恢复遵循[技术方案第 14 节](../docs/KnowledgeService-技术方案.md#14-部署升级与索引迁移)，不默认执行破坏性回退。
