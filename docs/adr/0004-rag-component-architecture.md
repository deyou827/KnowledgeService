# ADR-0004 核心 RAG 组件分工与工程布局

状态：已采纳（2026-10-20）；架构与选型决策，不表示依赖已安装、版本已锁定或能力已实现。

## 1. 目的与位置

解决原方案“接口边界清楚，但摄取和模型适配实现不够具体、真实混合检索偏晚”的问题。知识库独立拥有资产、权限、任务、证据与历史；平台只是未来调用方。本轮不修改平台 Runtime、不增加微服务、不开展新一轮存储选型。

## 2. 决策与选型原因

| 责任 | 默认实现 | 选择原因与代价 |
| --- | --- | --- |
| API 与业务用例 | FastAPI／Pydantic，项目 Application | 保留明确契约、授权与事务；不把业务藏进框架回调，代价是需要维护领域代码 |
| 摄取转换 | LlamaIndex Core＋已选格式解析器 | 复用转换与切分抽象；PAI-RAG 固定版本有明确依赖依据；需编写位置保真与类型转换适配 |
| LLM／Embedding | 项目 Provider＋LangChain 按需集成包 | 减少多模型协议适配代码，替代此前默认 HTTPX 手写封装；新增依赖升级和兼容测试成本 |
| Rerank | 独立 Provider＋合适集成或直接 API | 重排不强行模拟聊天协议；S3 接入与对照，是否默认启用由质量／延迟／成本决定 |
| 在线检索 | PostgreSQL／pgvector＋全文＋项目 RRF | 授权事实与候选查询同后端，减少基础设施；大规模和高级词法能力须实测，不宣称优于专用检索引擎 |
| 质量评测 | Ragas＋确定性测试＋人工抽检 | 复用质量指标而不自研整套评判器；评判模型有成本和偏差，不能替代安全测试 |
| 原文、任务、身份 | 沿用 BlobStorage、PostgreSQL Worker、OIDC／Keycloak | 限制本轮变更面，复用现有一致性与独立身份设计 |

只安装 `llama-index-core` 和确实使用的 reader／集成包；LangChain 使用核心与具体模型集成包，不引入 Agent 全家桶。首个兼容端点的模型适配可用 `langchain-openai`，其底层已有官方 SDK；不再并列维护一套相同的 SDK 封装。接口兼容不意味着模型功能、结构化输出、流式、错误码和计费语义完全一致，必须契约测试。

API、Worker 同一代码库，模型接入是进程内模块。单进程并发限制不能冒充全局限流；跨进程预算／配额经 PostgreSQL 协调，不新增 Redis 作为前置条件。

## 3. 框架边界与失效规则

1. LlamaIndex 只处理已授权内容的转换与切分；解析在隔离执行器中完成。项目用例依次调用转换、Embedding、暂存和发布契约，不由框架直接发布索引。
2. 不启用第二套权威 docstore／vector store 管理；框架 Node ID 不代替文档版本、Chunk ID 或引用定位。默认关闭框架内容缓存；以后开启须包含租户、文档版本、解析／切分配置和模型配置指纹，并纳入删除、保留及授权规则。
3. LangChain／LlamaIndex 类型不进入领域、持久化契约或 OpenAPI。模型仅从项目模型契约进入，避免 LlamaIndex 默认模型配置绕过外发许可和调用计费。
4. SDK 与框架不得各自叠加重试；由应用层统一处理 Attempt、截止时间、配额和 ADR-0003 的结果未知规则。无法关闭隐式重试的集成不作为默认适配。
5. Ragas 是离线质量任务，不阻塞在线问答启动。评判器调用同样需要模型配置、授权与预算，不自动上传员工问题到第三方观测或评测平台。
6. SSE 首版只流式报告安全进度与结果引用，正文在校验后由 GET Answer 完整交付，不在事件流缓存／重放；BFF 保管会话，KnowledgeService 对所有入口独立验证资源权限。

## 4. 采用与放弃的替代方案

- 不采用全量自研解析／模型封装：重复维护成本高；仍保留项目特有清洗、位置、权限和失败处理规则。
- 不采用 LangChain 包办所有业务：技术框架不应拥有文档版本、发布和授权权威。
- 不采用 LlamaIndex 与 LangChain 双检索链：仅一套 RetrievalService，避免双份索引状态、Prompt、重试和配置。
- LlamaIndex 全栈也是可行方案，并非不稳定；本项目选择其摄取能力与 LangChain 模型集成组合，代价是两框架版本与适配边界需要维护。PAI-RAG 使用 LlamaIndex 模型适配，不证明它采用了本项目组合。
- 不部署完整 RAGFlow／WeKnora 作为子系统：它们适合希望直接获得完整产品的场景；本项目已有独立契约、历史交付和权限要求。选择自建组合意味着更长交付周期与自行承担验证责任。
- 不增加 Agent／LangGraph、OCR、GraphRAG 和专用搜索集群；遇到明确业务缺口再按原门禁扩展。

## 5. 阶段与验收

S1a 锁定精确直接／传递依赖与哈希，区分 API、Worker、evaluation 依赖组；用架构测试约束框架导入边界。S2 用 Markdown 打通 LlamaIndex 转换、定位与任务发布。S3 将真实 Embedding、单库向量／全文／混合召回、Rerank 可配置接入及 Ragas 最小回归一起纳入核心闭环；S4 扩展格式、同步、知识治理与跨库，不再首次引入真实向量。

必须覆盖：页码／章节／行号保真、空解析与 OCR 需求显式失败、tokenizer 与向量维度一致、撤权前置过滤、删除后旧任务不发布、框架默认模型不触发、模型超时不隐式重调、引用校验和受控历史、词法／向量／混合及重排开关同集对照。

实际模型 ID、端点、维度、上下文、tokenizer、外发许可及预算仍是实施输入，不凭参考项目代替组织授权。Rerank 未配置时显式关闭并报告未评测；不得称为接入验收已完成。沿用既有 PRD 质量目标，不降低阈值换取通过。

上述决策的实现输入输出、配置、表关系、API 和测试细化在[核心链路详细设计](../KnowledgeService-核心链路详细设计.md)，其中显式禁用框架默认 Embedding／缓存、隐式重试与自动再切块；组件具体版本仍由 S1a 锁定并验证。

## 6. 版本与来源

本轮确认组件方向，没有生成锁文件或确认当前安全补丁组合。采用正式稳定发布、锁定依赖和制品，不用 latest／RC，不将上游依赖范围当本项目精确版本。存储安全门禁沿用 ADR-0001。
