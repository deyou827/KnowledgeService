# ADR-0003 平台解耦与远程能力契约

状态：已采纳（2026-10-19）。本记录以 KnowledgeService 独立产品为主，定义外部调用、身份、操作和交付契约；不表示接口已实现。平台是可选调用方，不按其旧知识问答实现设计兼容层。

## 1. 结论

采用“**知识服务拥有通用能力，调用平台拥有适配责任**”的边界：

1. KnowledgeService 只暴露与平台无关的版本化 OpenAPI 和标准身份委托契约。
2. OrchestrationPlatform 侧实现 `RemoteKnowledgeProvider`／Adapter，负责把平台的 Project、Run、RunStep 和平台状态转换为知识服务能理解的通用请求。
3. KnowledgeService 不导入、持久化或依赖平台的模块、数据库、队列、ORM、DTO、凭据或运行时生命周期。
4. KnowledgeService 的 API 可以接受一个不透明的 `correlation_id`，但不解释它、不据此授权、不把它建模为 `run_id` 或 `run_step_id`。
5. 答案、EvidenceSet、引用和知识权限以 KnowledgeService 为权威；平台只保存跨系统引用和自己的运行关联，不复制为另一套知识事实。

平台集成是一个边缘适配器，不是 KnowledgeService 的领域模块，也不是把平台概念反向写入知识服务的公共契约。

## 2. 边界定义

### 2.1 KnowledgeService 负责

- Tenant、Workspace、KnowledgeBase、Document、Publication、EvidenceSet、Answer 等知识领域事实。
- 用户身份验证、服务身份验证、委托有效性检查和知识资源授权。
- 搜索、回答、引用、交付、撤权回读和知识服务自己的审计、任务与用量。
- 通用错误、状态、版本、幂等、超时、证据和回读契约。
- 通过 `answer_id`、`evidence_set_id`、引用标识和过期／失效状态提供受控回读。

### 2.2 OrchestrationPlatform 负责

- `project_id` 到 KnowledgeService `workspace_id` 的显式配置映射。
- 平台用户、服务身份与受托用户之间的身份委托或令牌交换。
- 平台 `Run`／`RunStep`、超时、取消、重试和平台审计与 KnowledgeService 请求的关联。
- 将平台请求转换成通用 `/v1` 请求，将通用结果转换为平台自己的响应模型。
- 平台消息、UI、缓存和历史展示；展示前按服务契约回读并处理失效状态。

平台适配器可以知道平台的全部概念；KnowledgeService 不能为了适配器而增加这些概念。

### 2.3 明确禁止的反向依赖

KnowledgeService 的 `domain`、`capabilities`、`application`、`providers`、`api` 和 `worker` 不得出现以下内容：

- `project_id`、`run_id`、`run_step_id` 作为领域字段或授权依据；
- `knowledge_qa`、`StoredKnowledgeAnswer`、平台 Run／RunStep DTO；
- 导入 OrchestrationPlatform 的 Python／TypeScript 模块、数据库模型或共享包；
- 直接读取平台数据库、对象存储、队列、缓存或内部 HTTP 接口；
- 把平台管理员、平台服务账户或平台项目默认映射为知识库正文权限。

平台名称可以出现在集成说明和适配器测试中，但不能成为知识服务核心代码或通用 OpenAPI 的类型依赖。

## 3. 通用契约

### 3.1 请求上下文

通用请求只包含以下类别：

- 已验证的服务身份和受托主体；
- KnowledgeService 的 `tenant_id`、`workspace_id`、`knowledge_base_id` 或显式库列表；
- 用户问题、检索／回答策略、幂等键和截止时间；
- 可选的不透明 `correlation_id`。

`correlation_id` 只用于日志、审计和链路追踪，不参与资源授权、幂等判断或业务状态转换。平台可以把自己的运行标识放入其中，但服务不读取其格式或语义。

作用域不从任意客户端字段直接获得。服务必须根据验证后的主体、服务委托和自身授权数据重新计算有效范围；平台传递的项目映射只能作为已配置的调用输入，不能替代服务端授权。

### 3.2 响应与回读

通用回答响应只返回：

- `answer_id`、状态和安全交付信息；
- `evidence_set_id` 与引用标识；
- 可受当前权限保护的正文或正文不可交付状态；
- 不透明 `correlation_id` 和服务自己的 `request_id`。

知识服务不返回平台专属的 `run_id`、`run_step_id`、消息 ID 或 UI 状态。平台如需保存历史，只保存服务引用和展示所需的最小关联信息；任何缓存都不是知识事实来源，展示前必须按服务契约重新授权。

### 3.3 状态和错误映射

KnowledgeService 的 Answer 只表达 `answered`、`no_answer`、`clarification_needed` 三种业务结果，以及明确的能力／范围 warning。技术失败归 Operation，不创建 `Answer.failed`；失败请求历史关联 Operation，不通过伪造 Answer 保留。执行状态、回答结果和当前能否交付分别表达，唯一组合规则见第 5.4 节；调用方不能反过来要求知识服务新增平台状态。

错误保留通用 `error.code`、`retryable`、`request_id` 和 HTTP 语义。平台的重试、取消和用户提示由适配器处理，但不能把权限拒绝改写成无答案，也不能把证据失效改写成成功。

## 4. 身份与权限解耦

服务侧只依赖可验证的主体和调用客户端，不依赖平台用户对象。用户以 `issuer + subject` 映射，调用服务以受信签发方认证的客户端标识映射；不以邮箱、请求头中的 user_id 或 Project 名称识别主体。

平台适配器负责取得短期、受众限定的服务凭据或委托令牌；KnowledgeService 负责验证签名、issuer、audience、有效期、撤销边界和委托范围。有效权限始终是：

```text
服务允许动作 ∩ 受托用户当前权限 ∩ 委托范围 ∩ 请求资源范围
```

没有用户委托时，平台服务身份只能访问明确授权给服务自身的资源，不能自动继承平台管理员或项目成员权限。项目到 Workspace 的映射由平台适配器配置，但最终资源授权和存在性检查由 KnowledgeService 执行。

### 4.1 默认身份接入流程

1. 知识服务自己的门户使用 OIDC Code＋PKCE 和 BFF 会话，不经过平台；机器任务使用独立服务账户。
2. 代表用户调用时，调用应用持有真实用户 access token，以 confidential client 向同一受信 realm 执行标准 Token Exchange，申请知识服务 audience 和最小 scope。禁止仅凭服务凭据和任意用户名换取用户权限。
3. 默认 Keycloak access-token profile 验证签名与算法允许名单、精确匹配的 `iss`、包含本服务的 `aud`、`exp`、`iat`、存在时的 `nbf`，并要求非空 `sub`、已登记的 `azp` 和所需动作 scope。`iss + sub` 映射主体，`iss + azp` 映射认证客户端；缺少或未知的声明一律拒绝，不从请求体补齐、不回退猜测其他 claim。真实接入夹具证明交换令牌的 `azp` 对应 requester。企业 IdP 的其他声明只可经显式登记的 Identity Provider profile 映射为相同 AuthContext，不影响领域契约。
4. 知识服务重新检查主体启用状态、成员关系、服务允许动作和资源权限。scope 仅限制动作，不自动授予任何 Workspace／文档权限。未知主体或缺少客户端绑定时拒绝，不按邮箱自动合并账号。

默认只支持单跳、同 realm 的“用户身份＋认证客户端”调用 profile；它不是完整 RFC 8693 `act` 委托链实现。Keycloak 26.2.0 固定文档已将 Standard Token Exchange V2 列为受支持功能，但不等于所有委托／冒充模式均稳定可用。当前不依赖 Legacy／Preview、`requested_subject` 冒充或跨 realm 交换；跨域需求出现后另行决策，不自建签发服务兜底。

代表用户调用的 access token 默认签发寿命不超过 5 分钟，profile 校验 `exp - iat` 上限；不承诺交换结果自动受输入令牌剩余寿命约束，不向知识服务传 refresh token。`jti` 存在时用于审计／撤销定位，不当作幂等键或默认必需声明。令牌到期、BFF 退出、IdP 撤销和本地资源撤权是四种不同事件：BFF 退出立即失效本地会话；已签发 access token 若仅做离线校验，不能宣称随远端退出立即失效。正式接入须声明远端撤销传播上限及同步／检查机制，本地成员撤权不等待令牌到期。

三种入口显式登记：门户采用 OIDC Code＋PKCE／BFF，按当前用户权限访问；机器入口采用服务账户，只能访问授予该服务的资源；代表用户入口采用标准交换，按客户端允许范围与用户当前权限交集访问。账户类型由本地可信注册关系确定，不凭 `sub` 字符串外形识别，也不将机器账户自动解释成受托用户。登录入口按自己的 OIDC profile 校验，不误套委托入口的 scope 和寿命规则。

### 4.2 后台执行边界

任务只保存主体、客户端、动作范围和授权版本等必要事实，不持久化原始用户令牌。Worker 不是用过期 Token 重放 HTTP 请求：它凭内部任务权限执行已接纳的有限命令，并在外发、发布和交付等关键阶段重新检查当前授权。禁用主体、撤销服务授权或资源撤权均能阻断后续动作；任务事实不能成为长期通用委托凭据。

## 5. 操作与交付生命周期

### 5.1 四类标识

| 标识 | 所有者与语义 | 不承担的责任 |
| --- | --- | --- |
| `Idempotency-Key` | 客户端生成；同一命令重传复用 | 不标识用户、不用于追踪授权 |
| `operation_id` | 服务端生成；持久操作的查询与取消入口 | 不等同平台 Run，也不是结果正文 |
| `request_id` | 服务端为每次 HTTP 请求生成 | 重试不复用为业务唯一键 |
| `correlation_id` | 调用方可选、不透明关联值 | 不参与去重、授权和状态转换 |

创建导入、同步、回答等有副作用命令必须提供 `Idempotency-Key`。去重范围包含 Tenant、Workspace、认证客户端、有效主体、动作和目标，绑定规范化请求指纹；同键不同输入返回 409。事务内先去重，再预留额度、创建 Operation 和任务／Outbox，避免并发重复接纳。重试仍验证当前权限，不缓存并重放旧正文。

含 expected_change_seq／expected_version 的命令先验证当前权限并进行同键指纹判定，只有新命令才执行版本前置条件与 CAS。同键同参已接纳请求不会因自身写入改变版本而在重传时报冲突；版本前置值属于指纹，同键修改该值仍为异参冲突。此规则不允许已撤权者读取旧结果。

操作运行期间不得回收去重记录，终态后默认至少保留 24 小时；响应声明 `idempotency_expires_at`。过期后不保证复用旧键，调用方应先查已知 operation_id，不能自动重新执行未知费用请求。`correlation_id` 默认限制 128 个可打印字符，禁止携带正文／凭据，写日志时安全编码。

### 5.2 异步命令、取消与费用

- 导入、同步和回答默认 `202 + operation_id + Location`；摄取另返回 `job_id`。搜索仍为同步查询。`GET /v1/operations/{id}` 返回安全状态和结果引用，不直接返回答案／证据正文；正文走 Delivery 回读。
- Operation 是同一 PostgreSQL 中的公共操作记录，Job 表达实际工作，Attempt 表达一次执行、阶段与外部调用结果；三者不各自建立调度器。Worker 通过现有租约／fencing 执行，业务结果、Job 与 Operation 终态同事务提交，不承诺外部模型与数据库共享事务。
- 状态为 `queued → running → succeeded / failed / cancelled / timed_out`；排队时也可因授权或依赖失败进入 failed。取消请求记录为 `cancel_requested_at`，不是额外状态；queued 可直接 cancelled，running 接受取消后尽力停止。只有完成、取消或期限处理取得终态才确定最终结果；取消标记不代表已取消，终态不可覆盖。`no_answer` 是成功执行后的业务结果，不是操作失败。
- `POST /v1/operations/{id}/cancel` 对重复取消幂等；非终态返回 202，终态返回 200 和实际状态，不谎称已撤销成功结果。取消与完成使用版本检查／fencing 决胜；取消或期限先取得终态时，迟到结果不得提交为可读答案。
- 网络断开不代表服务端取消。客户端超时后先查询或同键重传；服务端使用接纳时确定的截止时间，重试不延长。过期排队任务不启动外部模型；执行中尽力取消 Provider，但不承诺撤回已发生的模型费用。
- 暂态失败仅在同一操作内按第 5.5 节的安全分类和有限重试预算恢复；终态失败不因旧键重传重新运行。用户明确重新执行时使用新键，并提示可能产生额外费用。上游结果未知与费用未知分开记录，不盲目再次生成。
- 查询／取消检查操作所有者和当前动作权限；管理员仅能按显式运维权限查看元数据或取消，不能借此取得问题和答案。资源已撤权时最多保留授权所有者可见的安全失败／取消状态，不泄露库名、提示词或引用。

### 5.3 数据归属与回读

| 数据 | 权威归属与保留规则 | 外部调用方边界 |
| --- | --- | --- |
| 用户问题／查询范围 | 知识服务受控问答记录；历史隐私、保留与删除策略覆盖 | 平台自行接收的输入归平台管理，不自动变成知识服务可分享历史 |
| Answer 正文／Citation | 知识服务保存；历史默认仅提问者可读，所有读取走 Delivery | 只长期保存 answer_id 与本地会话关联，不复制知识答案正文 |
| EvidenceSet | 全部模型输入证据的引用、版本与指纹；原文在资产存储 | 标识不是访问凭据，不保留片段副本作回读兜底 |
| Operation／用量／审计 | 知识服务安全元数据，独立保留期；无问题、证据和 Token | 只保存必要状态和关联，不从日志重建正文 |
| 平台会话／Run | 调用方自己的权威事实与披露规则 | 不反向成为知识资源授权来源 |

历史回读顺序：调用方检查会话可见性 → 以**当前查看者**取得有效身份 → 知识服务检查历史所有者／明确共享许可、原查询范围和全部 EvidenceSet 的当前权限／可用性 → 成功才返回正文。不能沿用原提问者身份向另一个会话成员展示；首条外部链路仅支持提问者本人回读，群聊共享不作为默认交付。

Answer 的生成结果不被历史撤权改写。单独返回交付状态 `available / unavailable`；记录本身不可见时统一 404，只有获准查看安全元数据的主体才得到不含资源细节的不可交付状态。依赖不可用时不得部分展示旧答案、问题摘要或引用；瞬时服务故障明确返回错误，不伪装为永久删除。

问答正文和引用响应使用 `Cache-Control: no-store`；前端权限变化、退出和重新验证期间清理或隐藏敏感内容，回读失败不得使用旧缓存。已下载或已送入外部模型的内容无法远程撤回，平台端生成不获得服务端 Answer 的完整交付保证。正式数据保留期限仍属组织配置，不由开源默认值代替。

### 5.4 状态组合与最小接口规格

| 层次 | 字段与取值 | 约束 |
| --- | --- | --- |
| 执行 | `operation_status: queued / running / succeeded / failed / cancelled / timed_out` | failed 带安全错误；取消时间为独立字段 |
| 回答 | `answer_status: answered / no_answer / clarification_needed` | 仅回答操作成功时创建 Answer；非成功终态没有可交付 answer_id |
| 交付 | `delivery_status: available / unavailable` | 仅对有权访问历史安全元数据者表达；记录不可见仍为 404，服务故障为非 2xx |

成功的回答操作在同一事务创建 Answer 并发布结果引用。Operation 查询不带正文；回读按当前授权计算 delivery_status，不将暂时不可交付写成 Operation 失败。模型、索引或引用故障归 Operation.failed；取消／超时先提交终态时丢弃迟到草稿。失败请求的问题存于独立受控问答记录，Operation／Attempt 只引用其标识，不将问题写入运维元数据。

S1a 的最小 OpenAPI 必须包含下表 schema、必需／可空字段、HTTP 状态和负向样例；本记录不代替尚未生成的 OpenAPI 文件。

2026-10-20 实施细化见[核心链路详细设计第 8 节](../KnowledgeService-核心链路详细设计.md#8-首批-api-规格)。人工审核采用“摄取准备成功 → 独立审核 → 新发布操作”，不增加 waiting_review 操作状态；SSE 仅传进度与 result_ref，正文始终经当前主体 GET Answer 的 Delivery 检查。

| 接口 | 最小响应／约束 |
| --- | --- |
| `POST /v1/answers` | 必需幂等键；202＋operation_id、operation_status、Location；不返回草稿 |
| `GET /v1/operations/{id}` | 状态、deadline_at、cancel_requested_at、结果引用或安全 error；运行中 idempotency_expires_at 为 null（不得清理），终态后给出实际到期时刻 |
| `POST /v1/operations/{id}/cancel` | 202 表示已接纳取消意图，200 表示已是终态；均返回实际状态 |
| `GET /v1/answers/{id}` | answer_status、delivery_status；仅 available 时带正文，unavailable 时省略正文／引用／问题摘要 |
| `GET /v1/answers/{id}/citations` | 与答案共用 Delivery 的全证据检查，不单独放行部分引用 |

接纳前错误保留 HTTP 语义；接纳后的错误由 Operation 返回。`retryable` 只提示暂态错误，不授权客户端更换幂等键或重启终态操作；断线恢复始终先查询或同键重传。

### 5.5 外部调用与恢复决策

保证的是幂等窗口内同键只接纳一个 Operation、有效业务结果只提交一次；不保证外部模型恰好调用一次。Provider 必须声明是否支持请求幂等、结果查询，以及哪些拒绝可确认没有执行，不能只凭 HTTP 状态推断。

| 可确认事实 | 默认动作 |
| --- | --- |
| 客户端断线或重复提交 | 同键返回原操作；不新建任务，结果正文仍须重新授权 |
| 请求确认尚未发送，或 Provider 明确确认未接纳且允许重试 | 同一操作内有限重试，共享截止时间和额度预算 |
| 429／5xx／超时，但不能确认是否已接纳 | 不按状态码直接重试；按结果未知处理 |
| 已发送但响应丢失，或 Worker 在调用后、持久化结果前退出 | 默认停止自动重新生成；若 Provider 明确支持查询或幂等恢复，才在有效授权／期限内恢复 |
| 有效结果已经持久化 | 返回同一结果引用，不再次生成 |
| 用户明确要求重新执行 | 新键、新 Operation；提醒旧调用可能已经发生费用 |

执行前持久化 Attempt 的调用意图、稳定调用标识和发送阶段。重启后若无法证明调用尚未发送，即保守视为结果未知，不直接重投模型请求；这允许少量未实际发送的任务需要人工重试，换取避免不确定调用自动重复。Provider 内部 SDK 自动重试必须关闭或统一计入上述决策和预算，不能绕过外层限制。

结果未知且尚无终态时：Operation.failed、`error.code=UPSTREAM_OUTCOME_UNKNOWN`、`retryable=false`；费用无法确认时单独记为 `pending_reconciliation`。若取消／超时已提交，保留原终态，仅补 Attempt 与用量记录。费用未知不等于结果未知：有效答案已持久化但账单未到时不撤销成功结果。没有上游查询能力时标注“无法自动核实”，由人工按可用账单处理，不承诺自动对账成功、不擅自估算零费用；迟到信息只补账，不自动重开操作。

## 6. 契约版本与测试

- `contracts/openapi/` 只维护平台无关的 `/v1` 契约；平台适配器不修改知识服务领域模型来追赶平台旧接口。
- KnowledgeService 提供通用契约测试和独立运行测试；使用合成主体、Workspace、Answer 和 EvidenceSet。
- OrchestrationPlatform 提供 Adapter 映射测试、委托身份测试、错误／状态转换测试和平台回读测试；可使用 KnowledgeService 的契约 Stub，不需要共享数据库。
- 端到端只验证一条首链路：平台请求 → 服务端回答 → 引用回读 → 撤权 → 平台显示失效；随后再扩展搜索、Bot 和工作流入口。
- 契约升级优先增加可选字段或新端点；平台适配器支持服务版本协商和能力发现，不要求服务知道调用方产品版本。

## 7. 独立运行验收

KnowledgeService 在没有 OrchestrationPlatform、平台数据库和平台凭据的环境中，必须能够：

1. 启动 API／Worker、完成迁移和健康检查；
2. 使用通用 CLI 或契约测试创建并授权测试主体、资料和 Workspace；
3. 完成导入、发布、搜索、回答、引用回读、撤权和审计；
4. 重启或替换平台调用方后不丢失知识事实，也不改变服务端授权；
5. 平台适配器停止运行时，服务自身管理和 API 能力仍可验收。

平台侧验收另行检查映射、委托、关联、回读和展示，不把平台链路通过当作知识服务独立验收通过。

## 8. 取舍

- **保留必要集成耦合：** 身份委托、Project→Workspace 映射、关联标识和响应适配必须存在，否则无法安全接入平台。
- **不追求零耦合：** 通过 HTTP／OpenAPI 隔离不等于平台不需要适配；适配器是显式边界，不隐藏差异。
- **不共享领域模型：** 会增加发布协调和数据泄漏风险；宁可在适配器中做字段映射。
- **不复制答案正文：** 可降低撤权后泄漏和双事实源风险，但平台展示必须承担回读延迟和失效状态处理。
- **不为解耦提前拆服务：** 当前仍是模块化单体＋Worker；解耦靠契约与依赖方向，不靠增加网络跳数。
