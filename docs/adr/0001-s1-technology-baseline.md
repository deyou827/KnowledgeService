# ADR-0001 S1 技术基线与对象存储选型

状态:已采纳(2026-10-15),对象存储部分在 S1b 样本验证后最终确认。

## 结论

S1 采用 Python + FastAPI + PostgreSQL，依赖版本如下表锁定。对象存储不选 MinIO，候选限定为 SeaweedFS，S1b 用样本验证 S3 能力后再确认。

## 背景

PRD 的 V-01、V-02 要求在 S1 前确定试点范围、对象存储、OIDC 会话方案和依赖版本。

## 决策

### V-01 试点范围

- 单租户试点，容量档位采用 PRD 9.3：100 个已注册用户、10 个并发搜索、10,000 份文档／100,000 个片段。该档位用于测试设计，不是容量承诺。
- 测试夹具仍使用至少两个租户、每租户两个空间，验证隔离。
- 角色、知识类型、审核和有效期策略沿用 PRD 第 3、7 节默认值；试点组织的真实角色清单待用户提供，不阻塞 S1a。

### 会话方案

沿用技术方案 6.1：OIDC Authorization Code + PKCE，API 侧会话（BFF），浏览器使用 HttpOnly、Secure、SameSite Cookie，状态变更接口加 CSRF 防护。S1a 用测试签发 JWT 夹具，S1b 接入本地 Keycloak。

### 对象存储

不选 MinIO。社区版在 2025-10 起停止发布二进制和镜像，2026-02-12 标为不再维护，2026-04-25 被永久锁定，不再有发布和保证的安全修复。商业版 AIStor 不符合自托管试点的成本。

候选比较：

| 候选 | 许可 | 对本方案的关键点 |
| --- | --- | --- |
| SeaweedFS | Apache 2.0 | 成熟度最高；组件较多，维护者集中；采用 |
| Garage | AGPLv3 | 体量小，但当前稳定版无对象版本和生命周期；方案需要版本与校验，淘汰 |
| RustFS | Apache 2.0 | 较新，仅见厂商自测数据；暂不采用，保持观察 |

SeaweedFS 对象版本、预签名、分片上传的行为本文来源未覆盖，S1b 必须用样本验证：不可变写入、校验和、版本、鉴权代理读取、删除与恢复清单对齐。验证不通过则回到本表重新选型。

对象存储通过 `BlobStorage` Capability 隔离（技术方案第 5 节），测试用内存替身必须标注，不替代真实链路验收。

## 放弃的备选

- MinIO：见上。
- 本地文件系统：只作测试替身，不满足企业验收的对象存储链路。
- 先写代码再选存储：对象存储决定不可变写入和恢复清单设计，晚选会推翻 S1b。
