# KnowledgeService 实施与验收计划

> 更新日期：2026-10-20
> 范围来源：[产品需求文档](KnowledgeService-产品需求文档.md)；实现边界：[技术方案](KnowledgeService-技术方案.md)

## 1. 结论

从完整企业目标中裁出可交付切片，先建立身份和事实边界，再完成知识链路，再扩展治理与运营。M0 只是中间里程碑；V1 必须完成 PRD 全部 P0，不以演示问答成功替代企业验收。

本文件不授权立刻开工。每阶段开始前讲清目的、系统位置、核心概念、与现有模块的连接和暂不做的范围；确认阶段后才实现。工程目录为 `/Users/lijinghua/Desktop/DD/work/KnowledgeService`，不在平台仓库内堆叠独立产品业务。

实施规格见[核心链路详细设计](KnowledgeService-核心链路详细设计.md)：第 3—6 节固定契约与业务流程，第 7 节分期建表，第 8 节为 OpenAPI 输入，第 9 节映射验收。S1a 先做基础表／身份夹具／操作契约，不一次建全量表；S2 摄取 ready_for_review 不等于发布；S3 用真实模型和同集对照验证，不以框架已引入冒充链路通过。

开工前 Review 的设计修订已收口，见详细设计 10.1。S1a 必须覆盖“已接纳写入改变版本后的同键重传”，S2 覆盖“草稿与发布版隔离、词法配置并存”，S3 覆盖“重排前／搜索响应前撤权及自然到期”；这些是待实现的测试门禁，不是本轮已执行结果。

| --- | --- | --- | --- | --- |
| S0 设计基线 | 企业目标与实施切片分离 | 本套 PRD、技术方案、参考矩阵及验证项 | 产品范围、角色和关键策略可解释；验证项有阶段归属 | 业务代码、部署、模型调用 |
| S1 企业基础 | 身份≠授权，模块≠服务 | OIDC／Keycloak、Tenant／Workspace、组与角色、库、对象存储、迁移、API 骨架、任务／审计基础 | 真实登录、作用域拒绝、对象读写授权、重启保留、OpenAPI 契约测试 | 多格式与真实问答 |
| S2 知识加工 | 原文／解析／片段／发布各自独立 | Markdown＋LlamaIndex 转换、持久任务、解析预览与修正、全文索引、修订／发布／撤回 | 位置保真、幂等、租约失效、并发更新、删除不复活；页面可观察；更新失败旧版可用 | 多格式、复杂连接器、ANN |

| S4 企业内容与检索 | 多形态知识统一治理，索引可替换 | Office／文本 PDF／网页、URL 定时同步、目录／标签、知识页面／FAQ、审核／有效期、授权跨库检索问答 | 格式与定位抽检、源失效、审批过期、模型切换、多格式质量回归、跨库授权 | OCR、完整协同编辑、GraphRAG |
| S5 质量与治理收口 | 质量运营是修复闭环，外部应用不等于用户 | 反馈与修复回归、评测、检索实验室、治理控制台、服务身份／用户委托、配额和审计 | FR-01—12 功能矩阵覆盖；共享许可、导出、预算、API 隔离测试 | 平台所有入口与企业连接器全集 |
| S6 企业试点放行 | 可演示≠可运行，备份≠已验证恢复 | 完整安全／故障／容量验收，保留与恢复策略、运维手册；达到 V1 | P0 门禁全部通过，实际基准与质量报告、恢复演练、已知限制清单 | 未经测量的高可用与规模承诺 |
| S7 平台集成 | 服务身份、用户委托、会话披露是不同边界 | 平台侧 RemoteKnowledgeProvider／Adapter 与一条端到端链路（单库、服务端回答、本人历史；按技术方案 15.1 目标契约接入） | 平台查询、引用、撤权、历史回读和 RunStep 关联；KnowledgeService 仍可脱离平台独立运行 | 旧问答迁移兼容、群聊共享、同时扩展所有 Bot／工作流 |

S1 就建立权限和任务事实，S5 是治理产品化收口，不是最后补安全。

S1 内部分两步，放行条件不变：

- S1a：用测试签发的 JWT 夹具和 PostgreSQL 建立 Tenant／Workspace、授权骨架、迁移、任务与审计基础，以及 OpenAPI 契约测试（含幂等、关联标识、错误结构）；按 ADR-0002 默认组件生成精确依赖锁，落实包布局与技术方案 2.2 的依赖方向自动检查，不重做技术栈选型。测试 JWT 不得当作真实 OIDC 验收。
- S1b：按 ADR-0001／0002 固定基础设施补丁镜像与 digest，接入真实 Keycloak 登录与服务端会话、对象存储，补齐真实登录、对象读写授权和重启保留验收；正式企业数据接入须满足安全及保留／备份责任门禁。

S3 同样分两步：S3a 真实 Embedding、授权单库混合检索、可配置 Rerank 与 EvidenceSet（仅 API 与测试）；S3b 回答、引用校验、交付检查、最小 Ragas 回归、个人历史和门户页面。各阶段遵循 API 与测试先行、页面后置。S4 拆为“多格式与同步”“知识治理”“跨库混合检索”三个可独立验证的小交付，逐个推进，不一次性铺开全部模块。

2026-10-20 按 ADR-0004 将真实向量与混合检索从 S4 提前至 S3，避免先建门户却未验证核心检索质量。S1a 增加框架导入边界与依赖分组锁定，S2 增加 LlamaIndex 类型／位置转换验收；不把框架接入当成解析质量已通过。Rerank 需有真实可用配置才可完成对照验收，默认启用与否是评估结论，不是另起选型；模型资源不足时如实报告未完成。

### 2.1 本轮契约优化的落地顺序

| 阶段 | 补齐内容 | 可判定的放行条件 |
| --- | --- | --- |
| S1a | 三类入口的身份 profile、Operation 最小状态机／幂等／错误与 ADR-0003 第 5.4 节最小 OpenAPI、合成夹具 | 精确 claims 与拒绝规则；状态组合、可空字段、取消标记、结果未知错误可判定；不同主体不能共享幂等结果；无平台内部依赖 |
| S2 | 导入／同步接入 Operation 和现有 PostgreSQL 任务 | 同键并发只接纳一次；异参冲突；重启可查；取消／完成／期限竞争只有一个终态 |
| S3b | 回答任务／Attempt、本人历史与统一 Delivery | 同键只接纳一个操作；持久化结果不重生成；调用后崩溃或响应丢失且结果未知时不自动重调模型；终态不重跑、撤权不泄漏、失败不创建 Answer |
| S5 | 标准交换的真实 Keycloak profile，机器／用户权限交集 | iss／aud／sub／azp／scope 和寿命上限验收；未知客户端、错误入口身份与撤权均拒绝；退出／远端撤销传播边界实测；不启用 Preview 冒充 |
| S6 | 幂等保留、费用待核对、恢复与敏感数据清理 | 活跃操作不丢去重记录；过期键行为明确；原文清理后历史不可交付；日志／审计无问题或令牌 |
| S7 | 目标 Adapter，不实现旧平台兼容层 | 当前查看者与历史所有者检查；会话无权先拒绝；服务不可用不回退正文缓存；平台停止不影响知识服务 |

Operation 与任务复用同一数据库／Worker，不为本轮设计增加中间件。以上是后续开发门禁，不是本轮已执行的测试。

S1a 定义契约与基础模型，S2 接摄取，S3b 接回答，属于先定接口再落业务，不是阶段冲突；不将全部业务实现提前塞入 S1a。本轮收口只更新设计，尚未生成正式 OpenAPI。身份 profile、状态与恢复规则、最小 OpenAPI 是 S1a 的三项明确产物，不新增全面选型阶段。

## 4. 验收方法

每阶段至少包含正常、异常、越权、并发或恢复中的适用样本；记录真实 Provider 与测试替身的差异。测试产物留在项目测试与 CI 中，不把普通调试流水复制进知识库。

### 4.1 必测企业场景

- 用户 A 能读而 B 不能读；同组撤权后搜索、引用、下载、历史和缓存同时遵循新策略。
- Tenant／Workspace 相同名称不能跨域授权；管理员的管理权不变成默认正文读取权。
- 文档修订并发发布、任务租约过期、删除时旧 Worker 重试，都不能覆盖新事实或复活资料。
- 来源超时与确认删除不同；审批后内容或解析变化不能沿用旧批准。
- 跨库检索遇到无权库、失效索引或通道故障，不静默放宽范围或伪装无答案。
- 模型引用合法但断言错误能被质量评测发现；非引用证据撤权同样使历史不可交付。
- 用户反馈不能让处理人绕过资料权限；评测与导出遵守外发策略。
- 服务账户不能自报用户冒充委托；平台会话不能永久显示已失效知识答案。
- 相同幂等键跨主体不能读出结果；同键异参冲突；操作完成／取消／超时并发不产生两个终态；cancel_requested_at 不是取消成功状态。
- Provider 确认未发送／未接纳才按预算重试；429／5xx／超时结果未知时停止自动重调。覆盖调用前意图落库、调用后崩溃、响应丢失、结果落库后断线和 SDK 隐式重试，验证同一操作与只提交一次的有效结果，不要求外部调用恰好一次。
- 结果未知返回 UPSTREAM_OUTCOME_UNKNOWN，费用未知记 pending_reconciliation；取消／超时后的迟到结果不能复活答案。有效结果和费用待核对可并存，无上游查询能力不得伪报对账完成。
- 回读必须使用当前查看者；有会话权限但无历史许可者不能借原提问者身份读取；问题摘要、引用、日志与缓存不形成旁路。
- 恢复演练验证对象完整性、当前撤权／删除状态和派生索引，不只验证数据库进程能启动。

### 4.2 测试层次与成本

领域与契约测试默认不调用模型；真实 PostgreSQL、对象存储、OIDC 集成单独运行；故障与并发测试作为发布门禁。质量评测固定数据和预算，调用前确认用户授权和外发范围。

前端常规验证运行开发编译、必要 lint 与相关测试，不默认生产构建。实际浏览器验收优先复用用户已打开的页面，不默认下载独立 Chromium。UI 实现前补齐开源交互参考的实际观察，不以 README 替代可用性验证。

## 5. 验证项与阶段输入

PRD 的 V-01—V-07 是唯一验证项编号，不另建冲突的决策清单。ADR-0002 已确定默认实现，以下分别是工程交付或业务环境输入，不是重新选型：

- S1：按默认角色／容量开发，生成依赖锁与镜像 digest，完成已选对象存储和 BFF 接入；真实人员映射在试点前确认。
- S2／S4：按已定解析库、分词、输入限制与同步初值实现，完成解析样本、中文检索、位置映射及来源异常验收。
- S3 前：真实模型运行位置、组织数据外发规则、预算与评测集。
- 正式企业数据接入前：确认保留与备份期限、目标、密钥／运维责任及适用安全修复；S6 前完成恢复实测、容量报告、质量阈值和告警响应。
- S5：按 ADR-0003 的同 realm 标准交换 profile 配置实际签发方、受众、认证客户端、claims 和撤销传播；独立身份接入不等待平台，不接受客户端自报用户身份。
- S7 前：平台侧完成 Project→Workspace 映射、目标身份 profile、操作与本人历史回读 Adapter；按技术方案 15.1 接入，不迁就旧平台 DTO，不将旧实现兼容性变成本服务前置条件。

参数不达标时先定位瓶颈或调整部署，再由用户确认范围变化；不能悄悄降低企业目标或删除失败样本。

## 6. 后续增强的触发条件

| 增强 | 触发条件 | 必须先证明 |
| --- | --- | --- |
| 企业来源连接器 | 试点知识确实来自相应系统 | API／许可可用，源权限和删除映射可验证 |
| OCR／复杂表格 | 扫描件或复杂版式构成主要缺口 | 解析保真、定位、成本及资源隔离 |
| Rerank 默认启用／多轮 | Rerank 接入与对照已在 S3；默认启用或增加多轮需明确收益 | 质量提升大于延迟成本，历史授权不被绕过 |
| Wiki 自动生成／GraphRAG | 多跳关系问题无法由现有检索满足 | 来源依赖、权限裁剪、更新失效和引用可验证 |
| OpenSearch／Milvus | 默认后端在目标规模或检索能力上不足 | 同数据集比较，迁移／追平／回滚安全 |
| 高可用／多服务 | 服务目标、吞吐或故障域提出明确要求 | 运维能力、数据恢复和一致性成本可承担 |

## 7. 完成定义

阶段完成必须能说明：解决了什么问题、模块如何连接、哪些能力真实验证、哪些仍未实现、下一阶段为什么必要。项目相关方案、核心设计和重要结论维护在本仓库 `docs/`，不沉淀普通调试和截图流水；跨项目通用学习可另记个人知识库，但不复制项目方案正文。

方案文档完成不等于 S1 已启动；M0 不等于 V1；V1 不等于平台集成或任意规模生产高可用。所有交付使用这些边界命名，避免通过名称制造完成感。
