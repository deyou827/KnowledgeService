# KnowledgeService 产品需求文档

> 更新日期：2026-10-15  
> 定位：独立企业级知识库产品；现行产品设计，不是功能完成报告  
> 配套：[技术方案](KnowledgeService-技术方案.md)、[开源借鉴与设计决策](KnowledgeService-开源借鉴与设计决策.md)、[实施与验收计划](KnowledgeService-实施与验收计划.md)

## 1. 结论与产品目标

KnowledgeService 将企业分散的资料转化为可管理、可检索、可引用、可授权和可持续改进的知识资产。交付形态同时包含面向员工的知识门户、面向维护者的知识工作台、面向管理员的治理控制台，以及面向应用的知识 API。

目标不是“上传文件后与模型聊天”，而是让企业回答四类问题：知识在哪里、哪些内容可信有效、谁可以使用、发现错误后如何修复。

建设原则：

1. 独立产品、自研核心流程与交互；允许使用数据库、解析库、模型 SDK 等基础组件，不直接包装整套开源知识库应用。
2. 目标按企业级设计，实施按可验证链路推进；学习贯穿解释、实现和验证，不把产品降格为教学 Demo。
3. 借鉴 WeKnora 的知识组织、RAGFlow 的解析可观察与校正、PAI-RAG 的服务化与治理思路，具体映射见参考文档。
4. 权限、版本、证据与质量是产品主流程，不是上线前补丁。
5. 不为“企业级”提前拆分微服务；默认实现单一，扩展通过契约完成。

### 1.1 业务价值与成功信号

| 企业问题 | 产品结果 | 衡量方式 |
| --- | --- | --- |
| 文档分散、重复找人问 | 员工在授权范围内搜索和问答 | 有效搜索率、答案有帮助率、找资料耗时抽样 |
| 资料过期、相互矛盾 | 明确负责人、版本、有效期和发布状态 | 过期资产占比、待处理反馈时长、更新时效 |
| 上传成功但实际不可用 | 可观察摄取、定位解析问题并修复 | 发布成功率、解析抽检、失败任务恢复率 |
| 权限失控、答案来源不明 | 授权检索、引用回读、审计 | 越权测试、撤权交付测试、引用与语义支持评测 |
| 调参凭直觉 | 固定评测集与策略对照 | 召回、拒答、质量、延迟与成本的版本化报告 |

业务指标先建立基线，再由试点确定提升目标；不能用点击率或引用合法率冒充知识准确性。

## 2. 产品边界与平台关系

### 2.1 产品包含

- 企业身份与空间协作、知识库及文档权限。
- 文件、网页及后续企业连接器接入，来源同步和知识生命周期管理。
- 文档、受控知识页面、FAQ、目录、标签、元数据与版本管理。
- 授权范围内统一搜索、检索问答、引用导航、个人历史与反馈。
- 解析与检索调试、评测、质量运营、审计、配额和运行管理。
- 独立 API、服务身份、用户委托与平台 Provider 接入。

### 2.2 与 OrchestrationPlatform 的职责分工

| KnowledgeService | OrchestrationPlatform |
| --- | --- |
| 知识资产、来源、解析、发布、索引、资源权限 | Agent、工具、Bot、工作流、会话披露规则 |
| 独立搜索问答、EvidenceSet、Answer、引用与历史 | 平台 Run／RunStep 和知识调用记录 |
| 知识领域审计、任务与质量运营 | 平台执行审计、审批与运行治理 |
| 知识服务自身模型配置与身份校验 | RemoteKnowledgeProvider 与平台身份委托 |

独立问答无需创建平台 Run；跨系统使用关联标识追踪。平台审批不代替知识发布审核，平台身份也不自动授予知识资源权限。

### 2.3 不纳入本产品

通用 Agent 工作流编辑器、工具市场、任意代码执行、通用 BI、Office 在线协同编辑、计费运营平台。它们不因参考项目具备而自动进入范围。

## 3. 企业角色、资源与权限

### 3.1 资源层次

`Tenant → Workspace → KnowledgeBase → Folder / Document / Page / FAQ`。

Tenant 表示组织隔离边界，Workspace 表示业务协作空间，KnowledgeBase 表示知识集合与治理策略。部门／用户组是主体组织方式，不等同于空间或知识库。目录负责组织和导航，首版不引入目录级 ACL 继承链；标签与目录也不能隐式授予权限。

首个企业试点可以只有一个 Tenant，但必须使用至少两个 Tenant 的测试夹具验证隔离。平台 project 与 Workspace 显式映射，不能用同名字符串自动授权。

### 3.2 角色矩阵

| 角色 | 主要职责 | 默认边界 |
| --- | --- | --- |
| 企业管理员 | 身份接入、用户组、空间、配额、审计策略 | 不因管理身份自动获得所有知识正文及用户问答历史 |
| 空间管理员 | 成员、知识库创建、空间治理 | 访问正文仍需知识库授权 |
| 知识库 Owner | 本库策略、成员、发布与生命周期管理 | 可读本库全部内容；不承诺对 Owner 保密 |
| Editor | 上传、维护、修订已授权资料 | 不自行扩大 ACL；受审核策略约束 |
| Reviewer | 审核已授权的待发布修订 | 审核角色不自动获得整库正文访问权 |
| Reader | 浏览、检索、问答及个人历史 | 仅可访问当前获准内容 |
| 质量运营者 | 评测、反馈处理、质量统计 | 数据集和证据仍受授权约束 |
| 服务账户 | 调用受限 API、同步或平台代理 | 绑定资源与动作；不默认代表任意用户 |

角色可以组合，但知识读取、内容修改、发布审核、调试、模型管理和审计查看是独立动作。知识库可启用“作者不得审批自己的修订”。Owner 的管理覆盖行为须显式授权、填写原因并审计，不能暗中绕过审核策略。

### 3.3 权限规则

- 身份认证采用 OIDC；资源授权由知识服务决定，Token 中的组织声明不直接成为文档权限。
- 普通成员文档权限为知识库权限的进一步收窄；继承与显式空允许名单不同，空名单不代表公开。
- Reader 不获得检索内部调试、下载或外发权限；这些动作需独立授权。
- 详情、原文、片段、引用、附件、任务、历史、搜索建议、统计及导出均授权，不能仅保护问答接口。
- 权限收紧后，新授权决策立即使用当前策略；不等待索引重建或 Token 到期。已交付到用户设备的数据不能撤回。
- 回答历史默认仅提问者可读。管理员可以查看受控运维元数据，但不能据此读取员工问题与答案。

## 4. 产品目标与交付边界

### 4.1 三层交付

| 边界 | 含义 | 不应误称 |
| --- | --- | --- |
| M0 核心链路 | 在企业身份、作用域和持久化基础上跑通 Markdown 到证据问答 | 完整企业首版 |
| V1 企业试点版 | 本文全部 P0：多用户多空间、知识治理、混合检索、运营和恢复闭环 | 已证明任意规模高可用 |
| 后续增强 | P1／P2，按试点需求和实测收益排序 | 可绕过 P0 安全验收的替代品 |

P0 表示 V1 放行条件，不要求首阶段全部实现。技术方案中的扩展位置不等于已经提供对应能力。

### 4.2 需求与优先级

| 编号 | 能力 | 级别 | V1 范围与验收重点 |
| --- | --- | --- | --- |
| FR-01 | 身份与企业协作 | P0 | OIDC、成员／用户组、空间、RBAC、服务账户；跨租户／空间隔离 |
| FR-02 | 知识资产组织 | P0 | 知识库、目录、标签、元数据、负责人、搜索筛选、批量操作 |
| FR-03 | 文件与网页摄取 | P0 | Markdown、DOCX、XLSX、PPTX、文本 PDF、受控公开网页；持久任务与定位 |
| FR-04 | 来源与增量同步 | P0 | URL 集合连接器、手动／定时同步、游标或内容指纹、失败恢复、来源失效策略 |
| FR-05 | 内容生命周期 | P0 | 修订、发布、可选审核、有效期、替代关系、归档、删除；旧版服务与新版本原子发布 |
| FR-06 | 解析与知识维护 | P0 | 原文／解析／片段预览、解析产物修正、重处理；基础知识页面与结构化 FAQ |
| FR-07 | 搜索与检索 | P0 | 同空间授权跨库搜索，全文／向量／混合，标签和来源筛选；独立调试权限 |
| FR-08 | 证据问答 | P0 | 授权选库、单轮跨文档问答、阶段进度、结构化引用、无答案／需澄清／失败 |
| FR-09 | 历史与交付控制 | P0 | 个人历史、当前授权和版本重查、过期隐藏、缓存防泄漏 |
| FR-10 | 质量运营 | P0 | 回答反馈、问题处理队列、固定评测集、策略对比、知识修复后的回归 |
| FR-11 | 管理与运行保障 | P0 | 模型用途与凭据引用、配额、任务中心、审计、告警、备份恢复和保留策略 |
| FR-12 | 对外知识服务 | P0 | 版本化 Search／Answer／Citation API，服务身份、用户委托、限流、幂等与关联标识、`/v1` 兼容规则和契约测试 |
| FR-13 | 平台适配 | P1 | RemoteKnowledgeProvider、一条查询与撤权回读链路；不阻塞独立产品验收 |
| FR-14 | 企业来源扩展 | P1 | 按需求选择对象存储／企业文档系统连接器，定义源端 ACL 与删除映射 |
| FR-15 | 复杂解析与增强检索 | P1 | OCR、复杂表格、重排、多轮检索改写；逐项通过质量与成本评测 |
| FR-16 | 关系知识与规模演进 | P2 | Wiki 关系扩展、实体／关系／本体、GraphRAG、搜索后端迁移及高可用 |

基础知识页面是人维护的版本化内容，不等于自动生成 Wiki；FAQ 的问题与答案同样参与授权、发布和引用，不能作为绕过证据校验的快捷回答。

## 5. 业务场景与闭环

### 5.1 员工查找制度

员工登录 → 选择空间 → 搜索“差旅报销” → 按部门标签、类型及更新时间筛选 → 查看生效文档 → 发起问答 → 点击引用定位原文。

只返回有权且已发布有效的内容；不暴露隐藏文档标题、数量或搜索建议。不同制度冲突时展示来源和适用条件，无法判断时要求澄清，不由模型自行决定企业政策。

### 5.2 维护者更新制度

选择已有文档 → 上传新修订 → 检查解析与表格 → 修正派生解析结果或调整策略 → 提交审核 → 审核通过且索引就绪 → 发布 → 验证典型问题。

原文件保持不可变，修正生成新解析产物；更新失败时旧已发布版本继续服务。需要立即下线旧错误内容时使用撤回动作，不等待新版本加工完成。

### 5.3 审核者发布知识

待审核列表 → 查看内容差异、来源、权限及有效期 → 通过／驳回并填写意见 → 系统校验审批绑定的修订和加工产物 → 发布。

审核后内容或解析产物改变，原审批失效；技术重建若不改变已审批内容，也需记录构建策略与来源关联。审核与索引就绪是两个条件，不能把“审核通过”显示成“已可检索”。

### 5.4 来源同步与失效

管理员配置受控 URL 集合及目标库 → 维护者预览映射与访问范围 → 首次同步 → 定时检查变更 → 新建修订／记录未变更 → 展示延迟、失败与最近成功时间。

首版 URL 来源不携带可信企业 ACL，使用本地授权，不宣称同步源端权限。超时、403 或单次 404 不直接等同源文档删除；无法确认时标记来源异常并按库的新鲜度策略暂停交付或告警。确认删除或主动移除来源时立即使对应内容不可交付。企业连接器必须另行定义删除和撤权事件的可信度及最大传播时间。

### 5.5 质量运营与知识修复

用户提交“答案错误／过期／引用不支持／找不到答案” → 受控反馈队列 → 有权维护者定位资料或检索问题 → 修复知识／策略 → 回归固定问题集 → 关闭反馈并保留处理结论。

提交反馈时明确是否共享问题、回答和引用给处理人；默认只提交分类与非正文元数据。处理人无资料权限时不能因收到反馈获得内容，运营数据不成为旁路知识库。

### 5.6 应用调用

应用获得服务身份 → 明确以自身权限还是代表用户调用 → 提交查询范围 → 服务授权检索 → 返回证据或答案 → 应用按交付约束展示 → 回读时重新授权。

平台不能把已保存答案永久当作普通会话文本绕过回读检查。受管界面必须支持知识消息失效；无法做到的外部客户端应在接入契约中明确数据留存风险，不承诺可撤回复制内容。

## 6. 信息架构与关键交互

### 6.1 三个工作区域

| 区域 | 页面 | 用户任务 |
| --- | --- | --- |
| 知识门户 | 搜索首页、知识浏览、问答、个人历史 | 找到并使用可信知识 |
| 知识工作台 | 库与目录、资料详情、导入向导、来源同步、审核、任务、质量 | 维护知识并提升效果 |
| 治理控制台 | 组织与权限、应用身份、模型与配额、审计、运行状态 | 管理组织边界与运行风险 |

同一产品可以使用统一导航，但普通读者不面对分块参数、Embedding 维度或任务租约。高级配置分层呈现，默认策略先可用，再按权限展开。

### 6.2 核心页面规格

| 页面 | 主布局与交互 | 必须覆盖的异常 |
| --- | --- | --- |
| 搜索门户 | 搜索框、授权范围选择、筛选侧栏、结果摘要、来源／有效期标记、转问答 | 无命中、范围为空、索引不可用、部分库不可用 |
| 知识库工作台 | 目录树、资料表格、标签与状态筛选、负责人、批量操作 | 未发布、更新中、过期、失败但旧版可用；批量逐项反馈 |
| 导入向导 | 选择目标与来源 → 元数据／权限 → 解析策略预览 → 确认 → 任务进度 | 重复提交、类型不支持、超限、部分失败、权限不足 |
| 文档详情 | 左侧结构导航；中间原文／解析／片段／版本；侧边属性、权限与任务 | 无文本需 OCR、定位失效、版本变化、修正待发布 |
| 来源管理 | 连接状态、映射预览、同步周期、最近成功、积压与失败原因 | 凭据失效、源端不可达、权限映射不确定、暂停同步 |
| 检索实验室 | 条件与策略、分通道候选、融合排名、证据预算、对照实验 | 不同分数不可比、通道失败、索引版本不匹配 |
| 知识问答 | 范围提示、阶段状态、答案区、引用侧栏、反馈入口 | 无答案、需澄清、失败、资料变化、模型未配置 |
| 审核与质量 | 修订差异、审批动作、反馈队列、评测版本和回归结果 | 审批过期、处理人无权、评测数据失效 |
| 管理控制台 | 身份／资源策略、凭据引用、用量、运行状态、审计过滤 | 不回显密钥、依赖故障、配额耗尽、恢复未完成 |

部分库不可用不能静默缩小搜索范围；默认返回可解释失败。后续若开放部分结果，必须显式 opt-in、标注缺失范围且不泄漏未授权库信息。

### 6.3 引用与阅读体验

- 引用点击后定位具体页、段落、工作表／单元格、幻灯片或 Markdown 行，而不只是打开文件名。
- 显示当次证据与当前有效状态；版本不一致时不给用户混看新原文和旧答案。
- 原文预览首版提供安全文本／受控定位；不承诺完整 Office 渲染或 DOCX 页码一致。
- 回答生成先展示阶段进度，最终正文完成引用与权限校验后交付；不流式展示未校验草稿。
- 检查权限或版本时隐藏旧缓存；失败时不回退展示缓存正文。
- 页面支持键盘操作、清晰焦点和状态文字；门户适配移动端，密集管理页面优先桌面。

## 7. 内容状态与治理规则

### 7.1 多维状态，不用一个“成功”概括

- 治理：草稿、待审核、通过、驳回、发布、撤回、过期、归档、删除。
- 加工：排队、处理中、成功、失败、取消；另记录抓取／解析／分块／向量／索引阶段。
- 可查询性：必须同时满足有效发布、索引就绪、当前授权、未删除且未超出有效期。
- 来源健康：正常、延迟、异常、已确认失效，与加工成功独立显示。

### 7.2 历史、撤权与删除

回答的安全依赖是全部送入模型的证据，而不只是最终显示的引用。任一依赖证据撤权、删除、过期、被撤回或原文修订不再有效，整条答案正文与引用停止交付；不靠删除一个引用“修补”旧答案。

无关文档更新不使答案自动失效。只有分块或索引重建、原文未变时，是否仍可回读由证据快照保留和内容批准状态决定，不能仅比较全库索引 ID。证据快照是引用与指纹，不是正文副本；引用目标被物理清理后答案不可交付。

归档停止新查询与知识正文交付，保留必要管理元数据。逻辑删除立即禁止交付；物理清理由保留策略执行。历史列表、问题摘要、搜索建议和缓存同样受当前授权约束。

## 8. 数据、隐私与管理要求

- 原文件、网页快照、解析产物、向量、问答和评测数据分别定义用途、保留期、删除与备份政策。
- 资料正文和问题不进入普通技术日志。审计记录主体、动作、资源标识、结果和策略版本，不复制资料正文。
- 模型配置分 Answer／Embedding／Rerank 用途，清楚说明哪些内容会发送到外部服务；外发前应用组织策略。
- 首版控制台配置模型参数和凭据引用，不提供明文密钥持久化；凭据通过部署运行时或 SecretProvider 注入。未来密钥录入需单独设计加密、轮换与审计。
- 下载、导出、反馈共享、评测数据导出和后台模型调用均纳入授权与外发控制。
- 网页抓取、压缩文件、HTML／Markdown 展示和文档解析均按不可信输入处理。
- 组织配额涵盖存储、文档／片段、任务并发、查询速率和模型预算；后台重试也计入用量。

## 9. 验收矩阵与质量指标

### 9.1 固定数据集

功能集至少包含 60 份合成或获授权资产，覆盖 V1 格式、知识页面、FAQ、多库、修订、过期及受限资料；权限夹具至少两个租户、每租户两个空间、不同角色和用户组。

初始问题集至少 120 题：60 道可回答题（含跨文档、表格和术语变体）、30 道无答案题（至少 15 道相关但缺少所问事实）、30 道权限／版本／来源状态题。标签记录支持原文和答案要点，禁止为当前结果改标签。

### 9.2 发布门禁

| 维度 | 验收要求 | 性质 |
| --- | --- | --- |
| 身份与隔离 | 跨租户／空间／角色／组变更／服务委托测试全部通过 | 硬门禁 |
| 引用结构 | 引用全部属于本次授权证据，修订、位置和指纹一致；非法草稿不交付 | 硬门禁 |
| 生命周期 | 并发发布、删除不复活、有效期、撤权、回读和缓存测试全部通过 | 硬门禁 |
| 恢复 | Worker 重启、租约过期、依赖中断及备份恢复演练全部通过 | 硬门禁 |
| 检索 | 有权相关证据 Recall@10 ≥85%，按格式、语言、单库／跨库分别报告 | 待试点校准目标 |
| 无答案 | 无答案集正确拒答 ≥90%，单独报告相关但不足子集 | 待试点校准目标 |
| 语义支持 | 人工核验关键断言被原文支持 ≥90%；另报答案要点覆盖 | 待试点校准目标 |
| 产品闭环 | 5.1—5.6 的适用场景完成正常、异常、权限和恢复验收 | 硬门禁 |

小样本质量指标不证明生产泛化能力；正式试点前冻结数据、模型和目标。质量不足不能通过改名指标绕过。

### 9.3 容量与服务目标

V1 容量验证档位先按 100 个已注册用户、10 个并发搜索请求、10,000 份文档／100,000 个片段设计测试；这不是已证明的容量上限。实际文件大小、长度分布、授权过滤比例和硬件必须随报告记录。

候选目标：温缓存搜索 P95 ≤2 秒；回答生成单独统计首个阶段响应、总耗时与超时率；来源新鲜度按同步周期加处理时延衡量。模型调用不承诺跨供应商统一延迟。

自托管试点暂以服务月度可用性 99.5%、RPO ≤24 小时、RTO ≤4 小时作为部署评审起点；必须结合服务窗口、备份方式与恢复演练确认，单机 Compose 本身不提供这些保证。生产要求更高时由容量／故障域驱动扩展，不据此提前承诺高可用。

## 10. 设计决策与实施前验证

### 10.1 固定方向

独立企业产品；OIDC 与资源授权分离；PostgreSQL 业务事实＋对象存储原文件；默认 PostgreSQL＋pgvector 检索；契约优先和 Provider 替换；目标架构完整、按阶段实施；不复制整套开源应用。
